## virtual-camera project created

Created `D:\code\virtual-camera` (new repo, 92 files, commit 6e4b955, branch main)
by referencing the structure and CI conventions of `D:\code\virtual-scanner`.

- **Analysis of virtual-scanner**: 3 platform dirs + `.github/workflows/build-installers.yml`
  (resolve → windows/linux/macos jobs → softprops release), Windows = Inno Setup via
  install-qt-action + choco, Linux = hand-rolled dpkg-deb, macOS = pkgbuild with optional
  MACOS_* signing secrets and ad-hoc fallback + install.sh one-liner. Mirrored all of it.
- **Architecture**: Qt 6 Widgets GUI + CLI controller (Qt Multimedia decode, no FFmpeg);
  shared seqlock shared-memory frame protocol (core/include/vcam/SharedFrameProtocol.h);
  Windows = self-written DirectShow capture source filter (pure COM, ~15 files, no DShow
  baseclasses), macOS = CMIO Camera Extension in Swift (appex via raw swiftc, no Xcode
  project), Linux = direct v4l2loopback writer.
- Key constants: driver CLSID {D4A1F5B2-6E38-4C7A-9B2E-1F8D3A5C7E64}, shm names
  "Local\VirtualCameraFrame" / "virtualcamera_frame", bundle id com.dynamsoft.virtualcamera.
- Known risks (documented in code comments/README): exact CMIOExtension Swift API shape
  and OSSystemExtensionRequest `submit` selector need verification on a real Mac; local
  Windows VM is ARM64 with no MSVC so nothing was compiled locally — GitHub Actions is
  the build authority (same as virtual-scanner).
- Default CI Qt 6.8.2 (fallback 6.5.3 Windows / native macOS), macos-14 arm64 runner,
  universal Swift extension, arm64 Qt app.
